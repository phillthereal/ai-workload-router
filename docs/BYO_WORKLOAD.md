# Bring your own workload: `awr bench`

> Draft design note, 24 Nov 2026. The command described here is not built yet.

`awr bench tasks.jsonl` runs a user's own prompts through the same paired test as the published benchmark: every prompt is answered by the default rule and by frontier-only, and the report states cost cut and quality kept with 99% ranges. It answers "would routing save money on my prompts?" for one file. It is not a published result and can never write to a published path. Constants marked *(chosen)* are design choices, not measurements.

## 1. Input format
- JSONL, UTF-8, one JSON object per line. Blank lines are skipped. Allowed keys: `prompt` (required), `reference`, `scoring`, `task_type`, `difficulty`, `id`.
- `prompt`: a non-empty string after stripping. A list or object is refused as multi-turn (see 6).
- `id`: optional, matching `[A-Za-z0-9_.-]{1,64}`, unique in the file. Absent ids are generated by line order as `byo-0001`, `byo-0002`, ...
- `reference`: optional non-empty string. With it the row is checked by code (see 2). Without it the row is judged.
- `scoring`: optional, only with a `reference`: `final_answer` (default), `exact_match`, or `judge` (the reference is a rubric for the judge). `scoring` without `reference` is refused.
- `task_type`, `difficulty`: optional labels used ONLY for the report's breakdown, never for routing. The router gets `{id, prompt}` only, so a label cannot change what the API would do. Any value matching `[a-z0-9_-]{1,32}` is accepted, so users can use their own categories (`support_email`); values outside the four known types and three difficulties are shown as given. An absent label is replaced by the free lookup's prediction (`shared_lookup().classify`), computed once at load and shown with a `(predicted)` suffix so it never merges with a given label of the same name.
- Refused at load, before any call: a line that is not a JSON object, an unknown key (a typo such as `refernce` would silently turn a free code-checked row into a paid judged row), an empty prompt, a bad id or label, a duplicate id, `scoring` without `reference`, a prompt that fails `gates.fits_context` for any model in its worst-case call list, and files over the limits in 6.
- Errors name the line and the key, never a value: `line 7: unknown key 'refernce'`. Key names are cut to 40 characters. No prompt, reference or answer text is ever printed, logged or written to the report.

## 2. How a row is scored, and `score_source`
- Both arms of a row always use the same scorer, so the pair stays fair.
- With a reference and `final_answer` (default): `scoring.final_answer`, which reads only the committed `Answer:` line. Because frontier-only does not add `FINAL_LINE` itself, the loader appends `api.FINAL_LINE` to the prompt once, before either arm sees it, when the prompt has no `Answer:`. Both arms get the identical prompt. Alternatives in a reference use ` || ` (`scoring.REFERENCE_SEP`).
- With `exact_match`: `scoring.exact_match`, no suffix added. It is loose (the reference anywhere in the reply), so it is opt-in.
- With `scoring: judge`, or no reference: `score(task, response, strict=True)` with `scoring="rubric_judge"`, so the real judge `claude-opus-4-8` scores it and any failure raises `JudgeError`. A row without reference gets this fixed rubric as `reference` *(chosen)*: "No reference answer was given. Score how correct, complete and suited to the task the candidate answer is." `score()` needs no other change.
- Mock run (`AWR_FORCE_MOCK=1`): every answer is simulated, so every row is scored by the offline mock judge `scoring.rubric_judge` using the predicted labels, exactly like `web._score` does for a simulated answer. Code-checking fake text against a real reference would give meaningless zeros.
- `score_source` per row, stored in the run log's existing `quality_source` column: `reference` (code check against the user's key), `judge` (Opus judge, with the user's rubric or the fixed one), `simulated` (the answer was simulated; checked first, as in `web._score`). There is no `unavailable`: a capped run stops instead.
- Headline: ONE cost-cut line and ONE quality-kept line over all rows, with the source mix written in the same line ("<x>% of rows checked against your reference, <y>% judged with no answer key"). Below it, one quality-kept line per source with its own range, and how many `judge` rows had a user rubric. Chosen over refusing a mixed headline because each row is paired with itself, so the ratio stays valid; the split shows where it comes from.
- What the judge cannot do: with no answer key it scores how good an answer looks, not whether it is true. Opus judges and Opus is also the frontier arm, so self-preference may favour that arm. Judges share blind spots with the models they grade. A prompt that quotes outside text (customer emails, web pages) can carry instructions aimed at the judge. Strict mode stops on an unparseable score but cannot detect a steered one.

## 3. What the report promises
- The benchmark's paired design: each row answered by `default_policy()` (the API default prompt version and `shared_lookup()`, since there is nothing to replay) and by `FrontierOnlyPolicy`, strategy names `router` and `frontier_only` unchanged.
- Cost cut is net of routing cost (every discarded answer counts). Quality kept = router mean / frontier mean.
- 99% ranges by paired bootstrap over whole rows: `bootstrap(pairs, stat, alpha=0.01)` with `net_reduction` and `retention`, 10,000 resamples, the same seed. These three functions plus `N_BOOT` and `SEED` move from `analyze.py` into `src/router/benchmark/stats.py`; `analyze.py` and the experiments re-import them, so their output is byte-identical. Pairs are built in memory from the run (`analyze.paired_tasks` reads only real rows, which would drop a mock run). A resample whose frontier mean is 0 makes retention undefined; the report prints "undefined" rather than crash.
- Breakdowns by task type, difficulty and `score_source`, each with n. The `simulated` flag per model from `BenchmarkReport.model_simulated`, and a LIVE / SIMULATED stamp. Counts of degraded results and of answers that hit the 1,024-token ceiling.
- Verdict, against `report.COST_REDUCTION_TARGET_PCT` and `QUALITY_RETENTION_TARGET_PCT` at the 99% bounds: "meets" when both lower bounds clear the targets, "misses" when either upper bound is below, else "not settled". Below 30 rows *(chosen)* the ranges are printed but the verdict reads "too few rows for a verdict": with fewer rows the 0.5% and 99.5% resample percentiles hinge on one or two rows. No verdict is printed for a simulated run. `build_report`'s point-estimate `hypothesis_passed` is never shown.
- Fixed closing line: a small file gives wide ranges; judged rows are a model's opinion; prices are list prices from `config.py`, not your bill; the frontier answer is the quality baseline, not the truth; one run on one file says nothing about other workloads.
- The BYO report uses its own formatter (`format_byo_markdown`) over `build_report`'s numbers, because `format_report_markdown` prints the benchmark's point-estimate verdict.

## 4. Guard rails and spend
- Two modes only. Mock: `AWR_FORCE_MOCK=1`. Live: `--max-spend USD` (type `_spend_cap`), refused under `AWR_FORCE_MOCK`. With neither, the dry run prints and the command exits non-zero, saying which to set. No partially simulated mode: on a user's own data it would only confuse.
- A dry run is always printed first, with no calls. `--dry-run` prints it and exits. Per row: input tokens = `gates.estimate_prompt_tokens` of the prompt as sent (with any suffix); output = 1,024 tokens per call *(chosen: the adapters' `_MAX_TOKENS` ceiling, so it is a true upper bound while no effort config is sent)*; priced with `ModelConfig.cost_for_tokens` at list prices.
- Router arm worst case per row = the most expensive path the default rule can take, whatever the lookup predicts: classification (budget + mid + frontier), reasoning (Haiku 5.5 + mid + budget vote + Sonnet 5.5, per `_consensus`), extraction (Haiku 5.5 + mid + Sonnet 5.5), short writing (frontier, the rules table's top). Frontier arm: one frontier call per row. Judge: two Opus calls per judged row (one per arm), input = the judge template + prompt + reference + 1,024 candidate tokens.
- The dry run prints the worst case per arm, judge cost, total, and planned `score_source` counts as a live run would assign them.
- Rule: if the worst-case total exceeds `--max-spend`, refuse to start. No `--yes`. A stopped run writes no report, so money spent before a stop buys nothing; refusing up front is the only rule that never wastes it.
- During the run: `_preflight` on every model the run can call (roster tiers plus Haiku 5.5 and Sonnet 5.5), `_check_real` on every answer, `strict=True` scoring, `RunStopped` at the cap. The per-batch reserve passed to `_run_tasks` is the largest row worst case plus one frontier call, because a failover makes one extra paid call before `_check_real` stops the row. A stop prints `STOPPED: ... No report written.` as `run_benchmark.main` does.

## 5. Output
- Report: `data/byo/benchmark_report_byo_<stem>_<run_group>.md`, or `..._byo_simulated_<stem>_<run_group>.md` for a mock run. `<stem>` is the input name cut to `[A-Za-z0-9_-]{1,40}`. A subfolder can never equal a `run_benchmark._report_path` result, and the run group means a rerun never overwrites an earlier report. `data/byo/` is added to `.gitignore` so a private workload is not committed by accident.
- `--out PATH`: must end in `.md`, must not exist, and must not resolve inside the repo's `data/` folder except under `data/byo/`.
- Run log: a separate SQLite file, `data/byo/runs_byo.db` *(chosen)*, never `data/runs.db`, so BYO rows cannot become learned-policy evidence or enter `analyze.py` and the published tables. `run_group` is `byo-<timestamp>-<hex8>`; strategy names stay `router` / `frontier_only` so `build_report(run_group, db_path=...)` works unchanged.
- `prompt_text` is not stored and `response_text` is stored empty, since answers can quote the prompt. Both arms use `Router(use_cache=False)` and the judge gets a `use_cache` keyword (default `True`, threaded through `score` to `get_adapter`), so nothing from the file lands in `.cache/`.

## 6. Refused or out of scope
- Multi-turn rows, tool use, system prompts, images: refused or not supported.
- Files over 5 MB or 1,000 rows *(chosen: keeps the worst-case estimate readable and the run within one sitting)*.
- No `--judge` flag. Rows without a reference are judged automatically, and `"scoring": "judge"` on a row covers "judge this row even though it has a reference". A per-row field keeps the choice next to the reference it changes.
- Other policies (cascade, jury, learned, effort dial, `--classic`) are not offered: the command measures the default rule only.

## 7. CLI shape
- `awr bench tasks.jsonl [--max-spend 2.00] [--roster cross_vendor] [--workers N] [--out PATH] [--dry-run]`, in a new `src/router/cli.py` with one `bench` subcommand, and `awr = "router.cli:main"` in `[project.scripts]`. `--roster` swaps budget, mid and frontier; Haiku 5.5 and Sonnet 5.5 stay fixed in the default rule, and the help says so. `--workers` keeps the benchmark's latency caveat.
- `run_benchmark.py` is a root script, not importable from the installed package. So `_TASK_RESERVE_USD`, `_spend_cap`, `RunStopped`, `_check_real`, `_run_tasks` and `_preflight` move to `src/router/benchmark/guards.py`, and `run_benchmark.py` imports them back under the same names. `_run_tasks` gains `reserve=_TASK_RESERVE_USD` and `_preflight` gains `extra_models=()`; the defaults keep today's behaviour.
- Must stay byte-identical in `run_benchmark.py`: argparse help and messages, the `STOPPED:` text, `_report_path` filenames (`tests/test_report_paths.py`), and the attributes tests reach through the module (`run_benchmark._run_tasks`, `_check_real`, `RunStopped`, `SpendMeter`, `main`, `db`, `_build_parser`).
- New loading, estimating, scoring and formatting code lives in `src/router/benchmark/byo.py`; `cli.py` only parses arguments.

## 8. Offline test plan
- Fixture `tests/fixtures/byo_mixed.jsonl`, 5 rows: a reference with default `final_answer`; a reference with `exact_match`; a reference with `scoring: judge`; no reference; no reference with `task_type: support_email, difficulty: easy`.
- Loader: every refusal in 1 and 6 names its line number, and a sentinel string inside the prompt never appears in any error.
- Mock run (`AWR_FORCE_MOCK=1`, temp db, temp output folder, `CACHE_DIR` patched to a temp folder): output shows the dry run (worst case per arm, judge cost, planned sources 2 `reference` / 3 `judge`), then cost cut and quality kept with 99% ranges, the `score_source` table (5 of 5 `simulated`), `(predicted)` labels next to `support_email`, "too few rows for a verdict", and the closing line. The report lands at a `_byo_simulated_` name; `.cache/` and `data/runs.db` are untouched.
- Paths: `--out` into `data/` refused, existing file refused, and no BYO name equals any `_report_path` output across rosters and tags.
- Stubbed live path: `--max-spend` under `AWR_FORCE_MOCK` refused; neither mode refused after the dry run; worst case above the cap refused with zero adapter calls; the estimator matches a hand-worked row; preflight covers Haiku 5.5 and Sonnet 5.5; a simulated answer raises `RunStopped`; a judge reply that is prose raises `JudgeError`; both end in `STOPPED` with no report.
- Unchanged: the existing suite, `tests/test_analyze.py` after the stats move, and `scripts/check.sh`.
- The live path is covered by stubbed tests only. No paid call is made in building or testing this command, and the report and README must say so until a paid run is approved.

Open questions for the orchestrator: (1) separate `data/byo/runs_byo.db` versus `data/runs.db` with a `byo-` prefix; (2) mock runs score every row with the mock judge, so offline tests never exercise the reference scorer end to end, only row by row.
